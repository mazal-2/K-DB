## 什么是策略产品经理？
#### 1 策略

**理解策略**
- 在业务环境中，策略就是为了某个目标，针对特定对象，在特定场景下，根据一定规则采取相应行动，并通过结果不断优化。总结下来就是 **目标、对象、场景、行为、规则权重以及效果评估**六个方面。
- 这些目标可以包括：用户规模增长、转化率提高、用户留存等。
- 常见的策略包括：搜索策略、推荐策略、广告策略、风控策略和用户增长策略等。

- **比如京东的优惠券策略：如果目标是提高用户的购买转化率，系统可能会根据用户的历史购买、浏览行为、商品价格以及优惠敏感程度等特征，判断什么用户、在什么时间、应该发什么类型、什么额度的优惠券**。这套“如何判断 + 如何行动”的规则，就是一种策略。

**具体来说包括以下六个环节：**
- **目标（Why）**  
    提高用户的**购买转化率**，同时控制优惠成本。
- **对象（Who）**  
    针对不同类型的用户，例如新用户、老用户、高价值用户、价格敏感用户等。
- **场景/条件（When）**  
    用户浏览商品但迟迟没有购买、购物车商品长时间未结算，或者特定促销活动期间等。
- **行动（What）**  
    根据判断结果，向用户发放优惠券，或者提供不同的优惠权益。
- **规则/权重（How）**  
    根据用户历史购买、浏览行为、商品价格、优惠敏感程度等特征，决定**给谁发、什么时候发、发什么券、发多少额度**。
- **效果评估（Result）**  
    观察优惠券领取率、使用率、购买转化率、客单价以及优惠成本等指标，判断策略是否有效，并进一步调整策略。

- 也就是：提高转化率 → 找到合适的用户 → 判断合适的触发场景 → 发放优惠券 → 根据用户和商品特征决定优惠力度 → 看转化和成本 → 持续优化。

#### 2 策略产品经理

**2.1 工作内容**
- 无论是数据产品经理、AI产品经理还是策略产品经理，工作内容总是可以归结为**需求调研、产品规划、项目落地以及迭代优化**四个方面。
	- **需求调研：** 发现目前用户购买转化率较低的问题，通过用户访谈、业务反馈和数据分析，进一步了解**哪些用户没有购买、为什么没有购买，以及优惠券是否能够解决这个问题**。
	- **产品规划：** 根据业务目标设计优惠券策略，包括**什么用户、在什么场景下、发什么券、发多少**。同时定义用户特征、触发条件、策略规则、数据指标等，并通过PRD等文档明确产品方案。
	- **项目落地：** 与算法、研发、数据等团队协作，将策略规则真正落地到系统中。例如完成**用户特征**计算、**优惠券发放规则**、**策略配置后台**以及相关接口开发，并推动测试和上线。
	- **迭代优化:** 上线后观察**领取率、使用率、购买转化率、客单价、优惠成本、ROI**等指标，判断策略是否有效。如果发现**优惠成本过高或者转化提升不明显**，就进一步调整用户分层、触发条件和优惠力度。

**2.2 案例说明（基于产品sense假设）**

**① 项目背景**
假设某电商平台在经历前期流量红利后，用户规模逐渐进入瓶颈期，部门开始寻找新的增长机
当前正值秋冬换季，往年这一时期都是用户集中购买秋冬服装的节点。因此，业务部门希望**抓住换季消费机会，通过优惠活动进一步刺激服装品类消费，提升平台整体交易额。****


**② 发现问题**
策略产品经理接到需求后，并没有直接开始设计优惠券，而是首先通过历史交易数据分析用户的购买行为。

>平台日常的购买转化率明显**低于618、双11等大促期间**，验证发现**部分用户**在大促期间参与优惠券和满减活动订单的消费金额以及转化率会比日常更高。

进一步拆解用户行为后发现：
- 很多用户会浏览、收藏甚至加购秋冬服装，但最终没有购买；
- **不同用户对优惠券的敏感程度存在明显差异；**
- **部分用户本身购买意愿较强，即使不发券也会购买；**

因此，策略产品经理判断：
> **如果继续依赖节假日统一促销，可能无法充分利用换季期间的消费需求。并且为了有效提高总交易额，需要设计策略识别真正需要优惠刺激的用户。**

**③ 策略设计**

- **旧策略：** 主要在618、双11等大型促销节点统一发放优惠券或开展满减活动，日常较少进行主动干预。
- **新策略：** 通过**用户行为、所在地位位置、温度变化情况**等特征数据识别具有潜在换季购买需求的用户，根据用户特征**匹配不同的服装优惠券**。

**示例：**

| 用户  | 用户特征          | 当前行为       | 环境特征      | 新策略       |
| --- | ------------- | ---------- | --------- | --------- |
| A   | 经常购买服装、优惠敏感   | 最近连续浏览羽绒服  | 所在地气温持续下降 | 满300减50   |
| B   | 女装购买偏好明显      | 最近浏览、收藏秋装  | 当地进入换季降温期 | 女装满200减30 |
| C   | 经常使用优惠券、价格敏感  | 加购秋冬服装但未购买 | 所在地温度明显下降 | 满150减25   |
| D   | 很少购买服装、优惠敏感度低 | 近期无服装浏览或加购 | 当地气温变化不明显 | 暂不发券      |

**④ A/B实验**

**用户随机分组**
- **A组：旧策略**——不进行针对性的换季优惠干预；
- **B组：新策略**——根据用户特征匹配并发放换季服装优惠券。

**用户行为**：
进入APP首页 → 浏览秋冬服装 → 领取优惠券 → 选取衣服 → 加入购物车 → 点击支付 → 使用优惠券 → 完成购买

**漏斗模型**：

|行为环节|关注指标|
|---|---|
|进入APP / 浏览秋冬服装|页面访问人数、停留时长|
|领取优惠券|优惠券领取率|
|加入购物车|加购率|
|点击支付|下单率|
|使用优惠券|优惠券使用率|
|完成购买|**购买转化率、平均交易金额**|
|购买后|**退单率**|



**⑤ 结果观察**
经过一段时间的 A/B 实验，对两组用户的行为漏斗进行对比：

| 指标         | A组：旧策略 | B组：新策略 |      变化 |
| ---------- | -----: | -----: | ------: |
| 秋冬服装页面停留时长 |    42s |    51s |  +21.4% |
| 优惠券领取率     |  18.5% |  36.2% | +17.7pp |
| 加购率        |   8.6% |  11.4% |  +2.8pp |
| 订单支付率      |  62.3% |  68.7% |  +6.4pp |
| 优惠券使用率     |  41.2% |  64.8% | +23.6pp |
| 购买转化率      |   5.4% |   7.1% |  +1.7pp |
| 平均交易金额     |   ¥138 |   ¥146 |   +5.8% |
| 退单率        |   8.2% |   8.5% |  +0.3pp |

**发现：**
- 做完显著性检验之后，注意到实验组在**用户停留、优惠券领取、加购、支付以及最终购买转化**等环节均有明显提升，一定显著水平下可以认为**用户特征进行个性化优惠匹配**能够有效刺激用户的换季购买行为。
- **B组退单率略有上升**，说明优惠刺激虽然提升了购买，但可能也带来了一定的非理性购买，需要进一步关注。

**⑥ 策略迭代**

**下一步行动：**
- 观察哪些用户的转化提升最明显、哪些用户优惠成本较高，以及退单率上升主要集中在哪些人群。

**并进一步：**
- **优化用户分层**：减少对本身购买意愿较高用户的优惠；
- **调整优惠力度**：针对不同优惠敏感度匹配不同优惠；
- **优化触发条件**：结合浏览、加购、温度变化等信号判断最佳发券时机；
- **关注退单率**：避免通过过度优惠带来低质量订单。

#### 3 匹配策略

**3.1 用户特征**
- **用户特征**是对用户自身属性、历史行为和当前状态的描述，用来判断 **“这个用户是谁、有什么需求以及对优惠的敏感程度”**。 
- 常见特征：

| 特征     | 含义             | 作用              |
| ------ | -------------- | --------------- |
| 用户类型   | 新用户、老用户、高价值用户等 | 判断用户价值和运营目标     |
| 品类偏好   | 用户经常购买/浏览的商品类别 | 判断用户可能需要什么优惠    |
| 历史购买   | 购买频率、客单价、购买金额等 | 判断用户消费能力和购买习惯   |
| 浏览行为   | 最近浏览、加购但未购买的商品 | 判断用户当前购买意愿      |
| 优惠敏感度  | 历史优惠券领取、使用情况   | 判断用户是否容易被优惠刺激   |
| 活跃程度   | 最近登录、浏览、购买时间   | 判断用户当前是否处于活跃状态  |
| 当前购物状态 | 是否有商品加购、是否临近下单 | 判断是否需要在当前时机进行干预 |

**3.2 优惠券特征**
- **优惠券特征**则是对优惠券本身的描述，用来判断 **“这张券适合什么用户、能够提供多大的优惠以及使用门槛是什么”**。
- 常见特征:

| 特征   | 含义             | 作用             |
| ---- | -------------- | -------------- |
| 适用品类 | 美妆、食品、服装等      | 判断与用户兴趣是否匹配    |
| 优惠类型 | 满减、折扣、无门槛等     | 判断优惠方式         |
| 优惠额度 | 满100减20、9折等    | 判断优惠力度         |
| 使用门槛 | 满多少元才能使用       | 判断用户是否容易达到     |
| 有效期  | 优惠券可使用的时间      | 判断是否适合当前场景     |
| 适用商品 | 可以使用优惠券的具体商品范围 | 判断与用户当前需求的匹配程度 |
| 发放成本 | 企业提供优惠所需要承担的成本 | 控制策略成本         |

**3.3 环境特征等外部因素**
- 除了用户自身特征和优惠券特征，**用户所处的环境和当前上下文**也可能影响购买决策。环境特征主要回答 **“用户现在处于什么样的外部环境和场景？”**
- 常见特征：

| 特征    | 含义             | 作用              |
| ----- | -------------- | --------------- |
| 时间    | 工作日/周末、早晚、节假日等 | 判断用户当前的消费场景     |
| 地理位置  | 用户所在城市、地区等     | 判断地域性的消费需求      |
| 天气    | 温度、降雨、天气状况等    | 判断可能受到天气影响的消费需求 |
| 设备/渠道 | App、网页、小程序等    | 判断用户当前的使用场景     |
| 促销活动  | 大促、节日活动等       | 判断当前是否存在集中消费需求  |

**3.4 匹配机制**
- 围绕我们提高总交易额的目标，优惠券策略最终并不是为了 **“让本来就会买的人获得优惠。”** 而是希望找到 **“原本不一定会购买，但在优惠刺激下购买概率明显提高的用户。”** 
- 也就是 **在什么情况下，把什么优惠给什么用户，才能以合理的成本带来更多增量转化？**

- 匹配过程：形成一个闭环 **”识别用户 → 判断场景 → 匹配优惠 → 做出决策 → 观察结果 → 优化策略“**

| 步骤           | 主要工作               | 核心问题          |
| ------------ | ------------------ | ------------- |
| **① 用户特征识别** | 分析用户属性、历史行为和当前状态   | 这个用户是谁？有什么需求？ |
| **② 场景判断**   | 结合时间、位置、活动等判断当前状态  | 用户现在是否存在购买机会？ |
| **③ 优惠券匹配**  | 综合用户、场景和优惠券特征进行匹配  | 什么券最适合这个用户？   |
| **④ 策略决策**   | 决定是否发券、什么时候发、发什么券  | 给不给？给多少？      |
| **⑤ 效果评估**   | 观察转化、客单价、优惠成本等指标   | 这次策略是否真的有效？   |
| **⑥ 策略优化**   | 根据结果调整规则、用户分群和优惠力度 | 下一次怎么做得更好？    |

**3.5 场景举例（实际过程中可能需要利用机器学习算法对用户行为进行打分）:** 
- **用户A：** 最近连续浏览美妆商品，购物车中有一件 **120 元**的商品，过去也经常使用优惠券。
- 系统可能判断：
	- **用户特征**：对美妆感兴趣、优惠敏感；
	- **场景特征**：已经加购商品，存在较强购买意愿；
	- **优惠券特征**：美妆满100减20，能够覆盖当前商品；
	- **策略判断**：该优惠可能进一步推动用户完成购买。
- **用户B**：刚开始使用京东外卖，过去外卖消费较少，但最近几次下单主要集中在**饮品店**。
- 系统可能判断：
    - **用户特征**：外卖使用频率较低，但已经表现出对饮品品类的兴趣；
    - **场景特征**：用户刚开始使用平台，正处于培养消费习惯的阶段；
    - **策略判断**：相比直接提供通用优惠，更适合针对用户已经表现出兴趣的品类进行激励。

#### 4 总结

如果把上面的内容压缩成一句话：
**策略，就是为了某个目标，让系统在不同用户、不同场景下做出不同决策。**

而策略产品经理做的事情，就是把这种 **“如何决策”** 转化为可以被产品、算法和技术真正执行的规则，并通过数据不断验证和优化。
也就是：
**明确目标 → 识别用户 → 判断场景 → 制定规则 → 做出决策 → 数据验证 → 持续优化**

这也是策略产品和普通功能型产品比较大的区别：
**产品更多是在设计“用户怎么用”，而策略产品更关注“系统应该怎么判断、怎么决策”。**

当然，真实业务中的策略会比优惠券复杂得多，往往还会涉及**机器学习、用户/内容特征工程、实验设计以及大量业务规则**。但无论具体业务怎么变化，底层逻辑依然可以从这几个问题开始理解：**目标是什么？给谁？什么时候？做什么？为什么这么做？效果怎么样？**

## 二 策略产品实战
